# MediCare Clinical Decision Support System — API Contract

This document specifies the REST API endpoints, schemas, authentication requirements, and error states for the **MediCare** system.

> **Ownership Demarcation**:
> - Sections 1 through 4 are maintained by **Person 2** (Clinical Intelligence, Medical Reports, PubMed/RAG, Medicines & Interactions, External Integrations).
> - Section 5 (Predictions, Disease Classification, SHAP Explainers) is maintained strictly by **Person 1**.

---

## 1. Medical Records & Report Analysis Pipeline

### 1.1 Upload Lab Report
- **Endpoint**: `POST /api/v1/records/reports/upload/` (or `/api/v1/patient/reports/upload/`)
- **Permission**: Authenticated Patient (`IsPatient`)
- **Content-Type**: `multipart/form-data`
- **Request Body**:
  - `file` (File, required): PDF (`.pdf`) or Image (`.png`, `.jpg`, `.jpeg`, `.webp`), max 10 MB.
  - `title` (string, optional): Human-readable report title.
- **Validation**: Strict size (<=10MB), extension whitelist, MIME type whitelist, and magic byte signature verification.
- **Success Response** (`201 Created`):
```json
{
  "id": 14,
  "patient": 5,
  "patient_email": "patient@medicare.local",
  "file": "http://localhost:8000/media/reports/2026/09/a1b2c3d4e5.pdf",
  "title": "Comprehensive Metabolic Panel",
  "file_type": "pdf",
  "file_size": 152430,
  "extracted_text": "",
  "analysis_summary": "",
  "uploaded_at": "2026-09-17T18:00:00Z",
  "results": []
}
```

### 1.2 Analyze Medical Report / Extract Clinical Metrics
- **Endpoint**: `POST /api/v1/records/<record_id>/analyze/` (or `/api/v1/medical-records/<record_id>/analyze/`)
- **Permission**: Authenticated Patient (owner) or Authorized Doctor (`doctor_can_access_patient`)
- **Content-Type**: `application/json`
- **Request Body**:
  - `text` (string, optional): Text override. If omitted, binary file is decompressed and extracted automatically via PDF stream parser or OCR.
- **Success Response** (`200 OK`):
```json

      "test_name": "Fasting Blood Glucose",

      "flag": "high",
```

## 2. Assistant & PubMed Literature RAG

### 2.1 Send Assistant Chat Query (RAG Grounded)
- **Endpoint**: `POST /api/v1/assistant/chat/`
- **Permission**: Authenticated User (`patient` or `doctor`)
- **Content-Type**: `application/json`
- **Request Body**:
  - `prompt` (string, required): Clinical inquiry or question.
  - `conversation_id` (integer, optional): ID of existing conversation session to append message.
  - `patient_id` (integer, optional): Target patient ID. Patients may only pass their own ID. Doctors must be authorized via appointment or clinical relationship.
- **Success Response** (`200 OK`):
```json
{
  "conversation_id": 8,
  "message_id": 22,
  "query": "What are the latest guideline-directed therapies for hypertension?",
  "response": "Based on current clinical literature regarding 'hypertension', clinical management prioritizes early diagnostic clarification and guideline-directed medical therapy...",
  "citations": [
    {
      "pmid": "29146124",
      "title": "2017 ACC/AHA Guideline for the Prevention, Detection, Evaluation, and Management of High Blood Pressure in Adults",
      "journal": "Hypertension",
      "year": "2018",
      "authors": ["Whelton PK", "Carey RM", "Aronow WS"],
      "abstract": "The guideline provides recommendations on screening, prevention, and treatment...",
      "url": "https://pubmed.ncbi.nlm.nih.gov/29146124/"
    }
  ],
  "disclaimer": "This synthesized medical explanation is generated by an automated AI clinical assistant for educational and triage guidance only. It does not substitute for formal clinical evaluation, diagnosis, or personalized prescription by a licensed healthcare provider.",
  "patient_context_applied": true,
  "provider": "gemini",
  "model": "gemini-1.5-flash",
  "grounded": true,
  "created_at": "2026-09-17T18:05:00Z"
}
```

### 2.2 Assistant History
- **Endpoint**: `GET /api/v1/assistant/history/`
- **Permission**: Authenticated User (retrieves only own chat history)
- **Query Parameters**: `page` (integer, optional)
- **Success Response** (`200 OK`): Paginated conversation list with embedded messages and sources.

## 3. Medicines & Drug Interactions

### 3.1 Unified Medicine Interactions
- **Endpoint**: `POST /api/v1/medicines/interactions/`
- **Permission**: Authenticated User
- **Content-Type**: `application/json`
- **Supported Query Formats**:
  1. Explicit drug list:
     ```json
     { "drugs": ["Warfarin", "Aspirin"] }
     ```
  2. Single queried drug evaluated against patient's active prescriptions:
     ```json
     { "queried_drug": "Aspirin", "patient_id": 5 }
     ```
  3. Single drug evaluated against custom medication list:
     ```json
     { "queried_drug": "Aspirin", "current_medications": ["Warfarin"] }
     ```
- **Authorization**:
  - Patient users can only access their own active prescriptions.
  - Doctor users must have active clinical authorization (`doctor_can_access_patient`).
- **Success Response** (`200 OK`):
```json
{
  "drugs_analyzed": ["Aspirin", "Warfarin"],
  "interactions": [
    {
      "drug_a": "Aspirin",
      "drug_b": "Warfarin",
      "severity": "high",
      "explanation": "Concomitant use with aspirin increases the risk of severe bleeding and hemorrhage.",
      "evidence_source": "OpenFDA Drug Label (FDA)",
      "source_identifier": "openfda:drug_interactions"
    }
  ],
  "total_interactions": 1,
  "has_critical_interaction": true,
  "patient_id": 5,
  "patient_medications_loaded": 1,
  "status": "success",
  "cached": false,
  "providers_consulted": ["OpenFDA"]
}
```

### 3.2 OpenFDA Adverse Drug Reactions & Boxed Warnings
- **Endpoint**: `GET /api/v1/medicines/openfda/reactions/?drug=<name>&limit=<n>`
- **Permission**: Authenticated User
- **Success Response** (`200 OK`):
```json
{
  "drug": "ibuprofen",
  "adverse_reactions": [
    { "reaction": "Headache", "reported_cases": 1540 },
    { "reaction": "Nausea", "reported_cases": 1210 }
  ],
  "total_reactions": 2,
  "has_boxed_warning": true,
  "boxed_warnings": ["WARNING: Cardiovascular and Gastrointestinal Risk..."],
  "precautions": ["Patients with renal impairment..."],
  "status": "success",
  "cached": false
}
```

### 3.3 OpenFDA Pairwise Interactions (Compatibility Endpoint)
- **Endpoint**: `POST /api/v1/medicines/openfda/interactions/`
- **Permission**: Authenticated User
- **Request Body**: `{ "drugs": ["warfarin", "aspirin"] }`
- **Success Response** (`200 OK`): Matches `OpenFDAService.check_interactions` format.

## 4. External Integrations Architecture

### 4.1 DrugBank Client (`integrations.drugbank_client`)
- Configured via environment variables: `DRUGBANK_API_KEY`, `DRUGBANK_BASE_URL`.
- If unconfigured, returns safe transparent payload:
  `{"source": "DrugBank", "status": "unavailable", "configured": false, "message": "DrugBank API key not configured..."}` without throwing exceptions or fabricating synthetic drug records.

### 4.2 OpenFDA Client (`integrations.openfda_client`)
- Public functional adapter routing to canonical `OpenFDAService` in `apps.medicines.services.openfda_service`.
- Enforces 24-hour caching (`openfda:<prefix>:<id>`).

### 4.3 PubMed Client (`integrations.pubmed_client`)
- Public functional adapter routing to canonical `PubMedService` in `apps.assistant.services.pubmed_service`.
- Enforces 24-hour caching (`pubmed:search:<slug>:<limit>`).
